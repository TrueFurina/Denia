## 8. 【23:43 后续】时序 bug 修复与闭环

### 根因（推翻本文 §5 的初判）
§5 曾判为「出厂模板 `engine=pyttsx3` + isolated 运行时下 pywin32 COM 链路不通」。
**这个归因是错的。** 决定性对照：

| 场景 | 结果 |
|---|---|
| 副本内隔离 env `import pywintypes` / `import pyttsx3` | **rc=0** |
| 副本内隔离 env 走 `create_backend("pyttsx3").synthesize()` | **OK，43406 字节** |
| 副本内隔离 env 跑完整 `main.py --doctor` | **17 PASS / 2 WARN / 0 FAIL, rc=0** |
| 但 `verify_deps` 在装配流程内跑 | 1 FAIL `No module named 'pywintypes'` |

⇒ 包没问题，**是验收跑早了**：`install_deps()` 在 `tools/make_dist.py:402`
就调 `verify_deps()`，而 `_pth` 写入（:1218）与 pywin32 DLL 铺设（:1230）
发生在它**之后**。注释自己写着「隔离必须写在依赖装完之后」，验收却违反了它。

### 修复（`tools/make_dist.py`，+25 −3）
- `install_deps(..., *, defer_verify=False)`：新增延后验收开关，默认行为不变
- 主流程用 `defer_verify=True` 调用
- 在隔离段（_pth + DLL 铺设）之后、**闸门之前**统一调一次 `verify_deps`
- 只验一次，且验的是**最终交付形态**
