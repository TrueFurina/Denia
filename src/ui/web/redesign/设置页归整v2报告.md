## 一、先回答你的两个疑问

### Q1「自动退避高性能占用…能不能做个开关？还是说开关有只不过没找到？」

**结论：逻辑存在、后端键存在，但设置页从来没渲染过它 —— 你找不到是正常的。**

| # | 配置键 | 默认 | 作用 | 有 UI 吗 |
|---|---|---|---|---|
| 1 | `proactive.duplex_local_omni_unload_on_game` | `true` | 重负载（游戏/渲染）时**是否卸载本地模型让路** | ❌ 无（**且后端无写入接口**） |
| 2 | `cloud_duplex.prefer_cloud` | `false` | 让路时**是否改走云端陪你**（花钱） | ❌ 无（当前正式页明确注释「不再暴露」，但桥接层 `cdnPreferCloud` 和旧版页面都还在） |

代码实锤（`src/companion/proactive.py`）：
- `_duplex_mode_lock_loop`（5254 起）每 ~10s 轮询 GPU / 前台进程 / 游戏识别，命中重负载 → 累加 `_duplex_load_rounds`；
- `5590`：`if not self._cloud_duplex_prefer_cloud:` → 走 `_game_lock_unload_local()`（**卸载本地 + 静音，不花钱**）；
  `elif force_lock / recognized_game_lock / else` → `_switch_duplex_mode('realtime', …)`（**切云端，花钱**）；
- `7265 _game_lock_plan()` 是「当前设置下会发生什么」的**唯一真相源**，且已写明：
  `prefer_cloud=true` 但**云端不可用**时会补一句「你开了『游戏时切云端』但还没绑定云端模型，所以先按省显存的方式处理」。

⇒ 你说的「**没绑 Key 直接卸载模型、绑了 Key 可选退避至云端**」= 键 #2 的语义，**完全对上了**。
本轮把它做成了真开关（见下 §二 N1）。键 #1 后端没有 setter，故先做**只读展示**。

### Q2「操作电脑能不能独立出一个 agent 能力板块」→ 已独立成「Agent 能力」分类。

### Q3「云端容量不需要了，不删只不显示」→ 已整行 `hidden`（元素仍在 DOM）。

## 二、本轮（v2）新增改动

### N1 「高负载自动让路」开关组（新增，位于「通话与双工」，紧跟语音通话）

- 走的是**既有**后端接口 `Backend.saveDuplex({prefer_cloud})` → `webapp.save_duplex_settings` → `config.cloud_duplex.prefer_cloud`，**未改任何后端代码**。
- 真机实测（注入 Backend 桩）：
  - 初始 `prefer_cloud=false` → 开关关、不门控；
  - 点击 → `saveDuplex` **真的收到 `{prefer_cloud:true}`**，开关点亮 + toast「已开启：重负载时改用云端陪你（会消耗云端额度）」；
  - 再点 → 收到 `{prefer_cloud:false}`，开关熄灭；
  - 重载 `?pc=1` → 回显为**开**。
- **门控（UI 铁律：不隐藏、不禁用）**：未绑云端 Key 时开关**照常显示、照常可点**，点了：
  - 开关**不会**被打开（`locked` 琥珀描边）+ 下方 `#pcReason` 显示「还没绑定云端双工 Key…请到『模型与 API → 模型一览』绑定云端模型后再打开」；
  - toast 同步提示；`saveDuplex` **零调用**（实测 `saveCalls: 0`）。
- 「高负载时自动让路」那一条用**只读胶囊**「已开启 · 固定」表示（因为无写入接口），并在说明里写明「要能关需后端补一个 setter」。

### N2 「Agent 能力」独立板块

- 新建 tier `#agent`，插在「通话与双工」之后、「模型与 API」之前；`agentGrp` 从原「通话与双工 → 双工」组内**整体搬入**（id 原样保留 ⇒ 全部 JS 绑定不变）。
- 同步的四处（漏一处就会出现「导航有、吸顶头没有」）：
  1. 子导航按钮 `data-to="agent"`
  2. `TIER_META.agent`（名称/清单/吸顶副标题/图标 —— 子导航文案也由它派生）
  3. `OV_CATS` 新增「Agent 能力」卡
  4. `TIERS` 数组 + `overviewNav` 的 `MAP`（总览卡点击跳转）
- 默认状态：**全关**（启用电脑控制=关 / 聊天中调用工具=关 / 执行前确认=开 / 浏览器操作=关 / 命令行=关）；开启条件=需强模型（建议云端），弱模型会弹风险提醒，高危步骤仍弹确认。

### N3 「云端容量」只隐藏不删除

- `#modeCap` 所在整行 + 其解释 `note` 都加 `hidden data-legacy="capacity"`，**元素仍在 DOM**（`app_backend.js` 每 15s 的 `getCapacity()` 刷新照常安全执行）。
- ⚠️ 踩到一个真坑：`.srow{display:flex}` / `.seg{display:flex}` 这类**作者样式会盖掉 `hidden` 属性的 UA 默认 `display:none`** ⇒ 只加 `hidden` **看不出任何变化**。
  已补作用域兜底 CSS（不动全局 `[hidden]`）：
  ```css
  .srow[data-legacy="capacity"][hidden],
  .note[data-legacy="capacity"][hidden],
  #callEngine[hidden]{ display:none !important }
  ```
  实测：两行 `getComputedStyle().display === 'none'`，`#modeCap` 仍存在。

## 四、开关默认状态 × 开启条件（总表）

| 开关 | 默认 | 开启条件 |
|---|---|---|
| 语音互动 | **开** | 档位含云端双工 + 已绑 Key；缺则被门控（点了弹怎么解） |
