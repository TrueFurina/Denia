## 0. 一页速览（先看这个就够）

**双工这件事在代码里有三层配置，三层用的是三个不同的键，且各有各的读取方 —— 这是本次所有问题的总根。**

| 层 | 配置键 | 谁写 | 谁读 | 作用域 |
|---|---|---|---|---|
| ① 模型槽位层 | `cloud_omni.model / base_url / api_key` | 设置页总览气泡 → `set_model_slot` | 引擎构造 | 云端双工**用哪个模型** |
| ② 双工引擎层 | `proactive.duplex_mode` | 外壳引擎弹窗 / 设置页总开关 / 混合按钮（`save_duplex_settings`） | **启动恢复、常驻双工、能力概览、总览卡、门槛** | **桌宠常驻用哪个引擎（主真相源）** |
| ③ 通话引擎层 | `proactive.duplex_voice_engine` / `duplex_video_engine` | 设置页「双工引擎」段（`save_call_settings`） | 仅 `start_duplex_call` 拨号那一刻 | 拨号默认引擎 |

**一句话结论**：设置页「通话与双工 → 双工引擎」那四个按钮落在 **③**，而用户和 UI 其余部分都以为它在改 **②**。
⇒ 在那里选「本地全双工」，**不改常驻双工、重启后也回不去**。

**活证据（当前 `config.yaml`，已矛盾）**
```yaml
proactive:
  duplex_mode: realtime            # ← 启动按这个起（= 云端双工）
  duplex_voice_engine: local_omni  # ← 设置页「双工引擎」段写进来的（= 本地）
  duplex_video_engine: local_omni
```

## 1. 双工模型的 API 定义（后端真相清单）

### 1.1 模型槽位层 —— `src/llm/model_registry.py`

6 个槽位 = `位置(local/cloud) × 用途(duplex/chat/vision)`，**这层设计是干净的**。

| 槽位 | 读的配置节点 | 写入方式 |
|---|---|---|
| `cloud_duplex` | `cloud_omni.model` / `.base_url` / `.api_key` | `set_slot()` 只写这三个键 |
| `cloud_chat` | `text_chat.providers` 中 **`manual_provider` 指向的那个端口** | 只改该端口 |
| `cloud_vision` | `vision_models.active` → 对应条目 | 只改该条目 |
| `local_duplex` | **不是模型**：`proactive.duplex_mode ∈ {local_omni, local}` + `duplex_local_omni_endpoint` | 写 `duplex_mode` ⚠️ |
| `local_chat` | `ollama.model` | 只写该键 |
| `local_vision` | `ollama.vision_model` | 只写该键 |

> ⚠️ **本地双工槽是"引擎"不是"模型"** —— 它写的是全局引擎键 `duplex_mode`。它是六宫格里唯一**会波及其他功能**的一格（见问题 ⑨⑩）。

配套 API：`read_slot` / `set_slot` / `read_all` / `list_presets` / `presets_for` / **`diagnose(raw)`**（一致性体检，5 条规则）。

### 1.2 双工引擎层 —— `proactive.duplex_mode`（主真相源）

| 取值 | 语义 | UI 归一 |
|---|---|---|
| `realtime` | 云端真全双工（Qwen-Omni） | `cloud` |
| `local_omni` | 本地真全双工（Comni / MiniCPM-o） | `local` |
| `local` | **废弃**（旧 Ollama polling 路径，会假死） | `local` |
| `auto` | 按场景自动（空闲本地、游戏切云端） | `auto` |
| `False` / `"off"` | 关闭双工（纯文本聊天） | `off` |
| `True` | ⚠️ **只做看屏快照，不含语音双工** | 兜底显示 `cloud` |

- **启动读取点**：`proactive._apply_config`（约 8319-8331）+ `_sync_duplex_mode_from_cfg`（8732-8743）—— **只认 `duplex_mode`**。
- **热切换点**：`set_duplex_mode()`（6819）—— 只改运行时 `self._duplex_mode`，**不落盘**。

### 1.3 通话引擎层 —— `duplex_voice_engine` / `duplex_video_engine`

- **写**：`save_call_settings`（7768）/ `save_call_inference`（7479）—— 都有 `local → local_omni` 归一，避免旧路径。
- **读**：**只有** `start_duplex_call`（7974-7989）按 `call_mode` 取一次。
- 选择顺序是"三级覆盖"：`call_mode` 取配置 → 前端 `d.engine` 覆盖 → `auto/off/空` 一律兜底 `local_omni`。

### 1.4 通话相关 API 一览

| 接口 | 返回/作用 |
|---|---|
| `get_duplex_settings()` | `engine`(归一) / `cloud_omni{model,voice}` / **`voice_engine` / `video_engine`** / `decouple_screen_voice` / `gpu` |
| `get_tier_call_status()` | 通话按钮门槛：`can_call` + `reason` + `action` + `gate_table`（走 `mode_gates`） |
| `check_mode_gate({feature})` | 单功能门槛；`notify_mode_gate` 弹浮窗 |
| `get_call_status()` | 拨号振铃真值：`ready` / `status` / `model_loading` / `error_msg` |
| `get_duplex_capacity()` | 云端网关容量（排队/空闲 worker） |
| `_tier_gate_duplex_mode(pro, call_mode)` | 引擎切换前的档位门控 |

## 2. 外显界面 ↔ API 对应关系

| # | UI 元素 | 读什么 | 写什么 | 一致？ |
|---|---|---|---|---|
| ① | 通话与双工 → **双工引擎**段（4 按钮） | `getDuplex().engine`（=②） | `saveCallSettings` → **③** | ❌ **读写不同键** |
| ② | 通话与双工 → **双工语音互动**总开关 | `getDuplex().engine` | `saveDuplex({engine})` → ② | ✅ |
| ③ | 通话与双工 → **一键混合模式** | `getMixedMode()` | `saveDuplex({engine})` → ② | ✅ |
| ④ | 能力概览 → **语音双工** | `getDuplex().engine`（=②） | 只读 | ⚠️ 只反映常驻，不含③ |
| ⑤ | 总览卡 → **通话与双工** 状态胶囊 | `getDuplex().engine`（=②） | 点胶囊 → 改**全局引擎** | ⚠️ 语义误导 |
| ⑥ | 模型与 API → **六宫格 · 本地双工格** | `get_model_slots` | `setModelSlot` → ② | ⚠️ 与"每格独立"矛盾 |
| ⑦ | 外壳桌宠面板 → **引擎弹窗** | `getDuplex().engine` | `saveDuplex({engine})` → ② | ✅ |
| ⑧ | **通话模式弹窗**（`call_mode_modal.js`） | `getDuplex().cloud_omni.model` | 现场 `d.engine` 覆盖 | ❌ **完全无视①的选择** |

> 小结：**②③⑦ 走 `duplex_mode`；① 走 voice/video_engine；⑧ 谁都不认、现场再选一次。**
> 四个入口、两条写入路径、一个"现场覆盖"。

## 3. 通话 / 双工 / 外显 三者关联逻辑

```
                     ┌── 配置真相源 ──┐
   [启动]  proactive._apply_config 只读 ──► proactive.duplex_mode
                                              │
              ┌───────────────────────────────┼──────────────────────────┐
              ▼                               ▼                          ▼
       桌宠常驻双工引擎              能力概览 capVoice              总览卡 syncCallCard
       (真在跑什么)                 (只读指示)                    (只读胶囊)

   [拨号]  外壳按钮 ──► get_tier_call_status ──► mode_gates.evaluate(voice_call)
              │                (can_call / reason / action)
              │
              ▼  允许则进弹窗
        call_mode_modal.js ──► 用户现场二选一 ──► startDuplexBridged(media, engine)
              │                                            │
              │                                   engine 覆盖 ↓
              └──────────────────────────►  start_duplex_call
                          未覆盖时读 proactive.duplex_voice_engine / _video_engine
```

### 三条判定规则（现状）

**A. 通话按钮可用性**（唯一正确收敛的一处 ✅）
`mode_gates.evaluate(mode, "voice_call", ctx)` → `ctx = {has_key(cloud_omni.model+api_key), vram_gb, duplex_engine(duplex_mode 非布尔非空)}`
- 被卡时按钮**照常显示、照常可点**（`.locked` + `cursor:help`），点了弹「为什么 + 怎么解」（`notifyTierCallBlocked` + toast 兜底）。
- 拨号时 **`start_duplex_call` 再用 `pro.capabilities()` 硬拦第二层**。

**B. 展示规则**：概览/卡片/门槛**全部读 `duplex_mode`**；③ 的取值**只体现拨号行为**。

**C. 三档 × 通话**（`MODE_PROFILES`）

| 档位 | `voice_call` | 说明 |
|---|---|---|
| 纯本地 | `local` | 走本地双工（需 ≥14GB 显存门槛） |
| 云端 | `cloud` | 走云端双工（需 Key） |
| 混合 | `local` + **`voice_call_alt: cloud`** | 默认本地，允许切云端（避免"混合档锁死云端通话"） |

## 6. 附：一句话记住每层的"看什么"

- 想知道**桌宠常驻真在跑什么** → `proactive.duplex_mode`
- 想知道**拨号会用哪个引擎** → `proactive.duplex_voice_engine` / `duplex_video_engine`
- 想知道**云端双工用哪个模型** → `cloud_omni.model`
- 想知道**能不能打电话** → `mode_gates.evaluate(mode, "voice_call")`
- **改双工引擎应当只改一处**：`proactive.duplex_mode`（其余两处应派生，不该独立存在）
