## 5. 实现约束与一个真问题（重要）

### 5.1 「只改 HTML」是怎么保证的
- **凡删除的元素**，都先核对了 JS 取值处是否有空值守卫：
  `callEngine` / `voiceDuplexSwitch` / `mixedModeBtn` / `gameCloudWatchSwitch` → 本页内联脚本里全是 `if (!x) return` 或 `if (x){…}`。
- **凡 JS 无守卫的元素**（`visSwitch` / `desktopWatchSwitch` / `agentGrp` / `sliceRow` / `pubjavisOpts` / `styleSeg`）→ **一律只搬移、不删除**，`id` 原样保留，所以绑定照旧生效。

### 5.2 ⚠️ 顺带查出一个真问题：`#callEngine` 有**两套独立绑定**
删掉引擎段后真机立刻报错：
```
TypeError: Cannot read properties of null (reading 'querySelectorAll')
    at voice_tier.js:432
```
`voice_tier.js`（外部脚本）也绑了同一个控件，而且**没有空值守卫**：
```js
callEngine.querySelectorAll('button').forEach(b => b.addEventListener('click', …));
```
本页内联的那份有守卫、外部那份没有 —— **这就是「同一控件多处绑定」的典型隐患**（上一轮报告里提过的同类问题）。
**处理**：保留一个隐藏空壳，让它的 `querySelectorAll` 返回空集合（no-op），不报错也不显示任何按钮：
```html
<div class="seg" id="callEngine" hidden></div>
```
**建议**：后续把「双工引擎」的绑定**收敛到一处**（要么只留 `voice_tier.js`，要么只留本页内联），否则以后每次动这个控件都要记得改两个文件。

### 5.3 顺带说明两处「纯字符串」改动（非逻辑）
- FOLD 折叠名单：`callTier: ['双工', …]` → `['云端双工 · 容量与端点']`（因为 §3-M3 改了分组标题，不改就折不上）。
- 三处分类描述（`TIER_META` / 吸顶头 `MAP` / 总览卡 `OV_CATS`）同步为「语音通话 · 看屏陪伴」。**只改文案字符串，未动任何判断逻辑。**
