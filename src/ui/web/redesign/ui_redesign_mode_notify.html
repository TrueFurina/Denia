描述词：从内部术语到人话

原则：讲清「发生了什么 → 为什么 → 对你有什么影响」，永不出现内部词。
改之前（用户看不懂）改之后为什么这样改

以后写这类文案的规矩

新增任何切换提醒都照这几条来，避免又冒出内部词。
① 达妮娅第一人称

她在跟你说话，不是系统在播报。 已切换快照模式 · 我先退到云端啦

② 先说影响，再说原因

用户最关心"我会不会卡 / 你还能不能陪我"。数字和进程名放后面或省掉。

③ 代价要坦白

退云端会慢就直说"反应会慢一点点，别介意～"，不粉饰成"保障流畅"。

④ 内部词一律不出现

双工 / 快照 / 提示词 / 就绪 / 下发 / 锁 / 秒卸 / 外部显存占用 —— 全部有对应人话， 兜底走 mode_notify.humanize()。

⑤ 出错不吓人

不贴错误串，只说"没连上，我再试一次…"，让用户知道不用管。

⑥ 语气收在颜文字/波浪号

句尾用「～」轻收，完成态配 。不用感叹号堆情绪，不加 emoji 满屏。
