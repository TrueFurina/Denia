> 评判维度：**人性化**（语气自然、有温度、像人话）× **直白易懂**（零解释成本）。

## 一、总体结论

| 维度 | 评价 | 依据 |
|---|---|---|
| 直白易懂 | **B+** | "开=X；关=Y"的公式贯穿全页，含义清楚；但**术语泄漏**（yt-dlp/锚点/切片/量化包/world）和**未解释黑话**拉低了下限 |
| 人性化 | **C+** | 少数文案很有温度（见第二节），但 70% 的提示是同一种"开关说明书"腔——准确、机械、没有"人"味；**代称混乱**（达妮娅/她/AI 三种叫法并存）加重了割裂感 |

一句话：**这是个"工程师写给自己的设置页"，好消息是骨架极好，坏文案是局部病不是系统病。**

## 二、表现良好的部分（应保持的范式）

| 文案 | 为什么好 |
|---|---|
| `低 · 难插话 / 中 · 默认 / 高 · 易打断`（打断灵敏度） | 用**后果**命名档位而非参数值，零解释成本 |
| `开=按意思找（「上次说的那家店」也能命中）`（语义检索） | 用**具体场景**解释抽象功能，是全页最好的 hint |
| `关=只写不读（记了也不用）`（记忆注入） | 六个字讲清后果，还有一点幽默 |
| `主题与显示 · 一眼顺眼`、`长期记忆 —— 达妮娅记得你`、`同一个大脑，跨平台聊天、记忆、性格一致`（lead/横幅） | 有情绪、有温度，是"陪伴软件"该有的口吻 |
| `关=绝不操作电脑；开=可下指令让她操作`（电脑控制） | 边界清晰、后果明确，安全类文案的范本 |
| `洗好后点「拉取模型列表」校验`类**动词引导**（填地址→拉模型→填 Key） | 步骤化按钮命名，降低操作焦虑 |

**结论：好文案的共性 = 讲后果、讲场景、用"她"称呼、步骤化。改进就是把这个范式铺开。**

## 三、问题汇总（按严重度排序）

### P1 · 内部实现泄漏到用户眼前（13 处）
用户不需要知道、也无法理解的**工程细节**直接写在界面上：

| 原文 | 问题 | 建议改写 |
|---|---|---|
| `开=达妮娅取视频、看画面再聊（需联网+yt-dlp）` | `yt-dlp` 是下载器名字 | `（需联网）` |
| `收到图片时…写入长期记忆(world)` | `world` 是内部存储类型名 | `…并记下来` |
| `开=游戏里也点评（走确定性 OCR 判定，比纯看画面稳）` | "确定性判定"是实现术语 | `开=游戏里也点评（认得更稳）` |
| `选档位后点下载（魔塔国内源）` | 下载源是实现细节 | `选好档位点下载即可` |
| `QQ（NapCat / OneBot）`、`微信（Gewechat）`分组名 | 桥接器名。**但**横幅已解释"QQ 需另跑 NapCat"——保留一处即可 | 分组名改 `QQ`/`微信`，桥名只留横幅 |
| `开=先判断你这句要不要查记忆（省 token）` | `token` 用户未必懂 | `（省额度）` |
| `pubjavis 提示词微调 / 测试模式7（test3 原样保留可 A/B）` | 内部实验代号（折叠区，可容忍） | 至少把"A/B"改成"对比试" |
| `本地双工模型量化包` | "量化"是模型压缩术语 | `本地模型精简版（更小更快）` |

### P2 · 未解释的黑话（8 处）
| 原文 | 用户困惑点 | 建议 |
|---|---|---|
| `开=1 个锚点即可说；关=至少 2 个一致锚点` | "锚点"是什么？ | `开=看到一点相关就开口；关=要确认两眼才说（更少说错）` |
| `视觉切片数：越小推理越快…16~24 兼顾` | "切片"是抽帧术语 | `画面采样密度：越高看得越清、反应越慢` |
| `允许画面描述（字幕机式）` | "字幕机式"很妙但突兀 | 保留（好比喻），加一句 `开=像字幕一样偶尔描述画面` |
| `开=不说"你这操作"（归给视频里的人）` | 不解释什么场景 | `开=评论视频时不说"你这操作"（说的是视频里的人）` |
| `超过后按更新时间淘汰最旧的`（最大条目数） | 可以，但"淘汰"略生硬 | `存满后自动忘掉最旧的`（更有"记忆"的味道） |

### P3 · 代称不统一（全页性）
同一个人在文案里有三种叫法：**达妮娅 / 她 / AI**。尤其是社交区整页用 "AI"：
`收到图片时让 AI 看一眼并记记忆` —— 其它区都是"达妮娅/她"。**统一为"她"或"达妮娅"**（标签短处用"她"，横幅处用"达妮娅"）。

### P4 · 括号堆叠（可读性）
大量 hint 变成"主句（备注1）（备注2）"：
> `开=允许达妮娅在你的 QQ空间发说说 / 看动态（需你的登录态）` —— 尚可
> `仅「真人陪伴」生效：越小推理越快、互动越及时；过大则延迟高。16~24 兼顾清晰与速度（本地双工）` —— 两个信息维度挤一段

原则：**一条 hint 只讲一件事**；次要信息挪进折叠说明或删掉。

### P5 · 危险按钮措辞不对等（安全）
- `清空全部记忆` vs `清空对话记录`：前者无说明、后者有。危险按钮**必须**都说清范围与不可恢复性。
- `保存（重启软件后生效）`（社交区）是全页唯一需要重启的保存，但语音双工区的"游戏锁会卸本地双工"暗示即时生效——**生效时机应全局统一标注**。

### P6 · 测试模式系列（折叠区内，低优先级）
`测试模式3+` `测试模式3++` `测试模式3+++` `测试模式自定义+`——对用户是噪音，但这是你自用的实验区（已确认不外显），**不改**，只建议对照表里给这串加一句"这些是我自己调参用的，可以无视"。

## 五、改进方案（分三档执行）

**第一档 · 直接替换（P1 术语 + P3 代称，约 20 处，零风险）**
- 全局替换 `AI`→`她`（社交区 3 处）、删除 `yt-dlp/world/魔塔/确定性/token` 等实现词（13 处）
- 危险按钮补范围说明（`清空全部记忆` 加 "不可恢复，建议先导出"）

**第二档 · 逐条润色（P2 黑话 + P4 括号，约 15 处）**
- 按第四节对照表改写；一条 hint 只留一个信息维度
- "淘汰"→"忘掉"、"供应商 TTS"→"更自然但计费"

**第三档 · 范式推广（P6 折叠区 + 新文案规范，长期）**
- 把好文案的三条共性写进开发约定：**讲后果不讲参数、讲场景不讲机制、用"她"不用 "AI"**
- 新增 hint 时自检："用户读完需要再问一句吗？"

**不建议动的**：`开=X；关=Y` 的总范式（它保证了全页一致性，是资产不是负债）；测试模式系列命名（自用实验区）；已确认隐藏区块内的文案。

## 六、上下文压缩总结

**结论**
1. 直白性 B+：公式化句式全页一致，主要扣分项是 13 处实现词泄漏（yt-dlp/world/token/魔塔/OCR 判定）与 8 处黑话（锚点/切片/量化包/字幕机式）。
2. 人性化 C+：好范式已存在（后果式档位名、场景式例子、有温度的 lead），但 70% 是机械说明书腔；代称混乱（达妮娅/她/AI）是最大硬伤。
3. 危险操作文案不对等：`清空全部记忆` 无范围/不可恢复说明；保存生效时机（是否需重启）标注不统一。
