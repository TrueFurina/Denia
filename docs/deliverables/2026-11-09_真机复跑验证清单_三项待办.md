   ```
   .venv\Scripts\python.exe tools\verify_realline.py --selftest
   ```

## 1. 待办①：试听播放生命周期（孤儿 ffplay / 叠播）

### 操作
1. 打开「音色/语音」设置页，点一次**试听**，听到声音。
2. **在声音还在播的时候**，连点 3~5 次试听（验证抢占：不应出现多段声音叠在一起）。
3. **在声音还在播的时候直接关闭 App**（右上角关闭 / 任务栏退出）。
4. 关闭后**用耳朵听 10 秒**：不应还有 ffplay 继续出声。
5. 再查一次残留进程（PowerShell）：
   ```
   Get-Process ffplay -ErrorAction SilentlyContinue
   ```
   期望**无输出**（有输出 = 孤儿 ffplay，回归）。

### 日志关键字（`logs/voice_playback.log`）
| 关键字 | 含义 |
| --- | --- |
| `[系统音频播放] ffplay 独立进程播放` | 走了新的 `Popen` 路径（不是旧的 `subprocess.run`） |
| `[系统音频播放] ffplay 播放完成` | 播放正常结束，没卡在 `wait()` |
| `ffmpeg 解码失败` / `ffplay 播放失败` | 环境缺 ffmpeg/ffplay，属环境缺口，不是本修复回归 |

### 脚本能判 / 不能判
- ✅ 能判：播放路径是否走了 Popen、是否正常完成。
- ❌ 判不了：**关 App 后是否还在响**（需人耳）、**是否叠播**（需人耳）、
  **ffplay.exe 是否残留**（需 `Get-Process`）。这三项脚本会显式列进「未验项」。

## 2. 待办②：隐藏窗口 ≥30min 长跑

### 操作
1. 启动达妮娅，等模型加载完（启动宽限 120s 内不判死，属正常）。
2. **把窗口隐藏/最小化**（或切到别的虚拟桌面、锁屏），并保持 **≥30 分钟**。
   > WebView2 隐藏/最小化时 `setInterval` 会被节流到约 60s，这是**预期行为**，
   > 两阶段心跳应把它判成 `slow`，不是 `dead`。
3. 30 分钟后恢复窗口，确认她仍可交互（能对话、能拖动、没被反复重载）。
4. 保留 `logs/launch_runN.log`（或该轮的 `run_*.log`），传给脚本。

### 判据（与 `tools/probe_a5_env.py::CLASSIFY` 同口径）
| 允许出现 | 不许出现 |
| --- | --- |
| `[UI心跳] ...；不重载`、`判为后台定时器节流`、`心跳间隔 Ns（>30s 但 <180s）` | `判定为 UI 卡死`、`前端无响应`、`第 N/2 次尝试恢复`、`重载排队`、`Reload 无效` |
| `心跳已恢复`（recovered，允许） | 上述 dead/recover 任一条 = FAIL |

阈值（`src/ui/heartbeat_policy.py`）：`timeout=30s` / `grace=120s` /
`dead_timeout=180s` / `cooldown=60s` / `max_attempts=2`。
30s~180s 只判 `slow`（只告警、绝不重载）；≥180s 才真判死。

### 脚本能判 / 不能判
- ✅ 能判：日志时长 ≥30min、心跳行里有没有判死/重载、有没有 `[UI心跳]` 活动。
- ❌ 判不了：**窗口是否真被隐藏**（脚本只看日志时间跨度，看不到窗口可见性）、
  GPU/声卡/网络差异下的实际表现。这两项列进「未验项」，需人工记录。

## 3. 待办③：主循环冻结根因已除（看门狗 3625 次告警消失）

### 操作
1. 正常启动，跑一段**有业务活动**的长跑（建议 ≥30min，且期间真的聊过几句 /
   开过网课录制——纯空跑不算证据）。
2. 保留该轮 `logs/run_YYYYMMDD_HHMMSS.log`。
3. 不要只挑「安静时段」：course_recorder 自死锁是**每次新转写/画面变化**触发的，
   必须让网课录制或屏幕感知真的在跑才有意义。

### 判据
| 项 | 期望 |
| --- | --- |
| `【主循环看门狗】asyncio 主循环疑似卡死` | **0 条**（修复前单份日志曾 3625 条） |
| `logs/loop_freeze_*.log` | 文件存在**不算问题**（看门狗启动时无条件创建），但内容里不得有 `[loop_freeze] lag=` |
| 启动横幅 `达妮娅 AI 桌面伴侣` | 必须有，否则说明日志被轮转截断 → 判 UNKNOWN |
| 业务日志条数 | ≥20，防止「程序没真跑起来」的 0 告警假绿 |
| 日志时间跨度 | ≥ `--min-minutes`（默认 30） |

### 为什么脚本要这么啰嗦
「0 条告警」**不等于**「修好了」：空日志、程序没起来、只跑 10 秒、日志被轮转
冲掉开头，都是 0 条告警。所以脚本要求「启动横幅 + 业务活动 + 时间跨度」三件
证据齐才允许判 PASS；缺一件返回 **UNKNOWN**（退出码 77，不算通过）。
> 现存 `logs/run_20261106_225141.log` 开头就被轮转截断（首行是 TASK dump），
> 拿它跑会得到 UNKNOWN——这是**正确的反假绿行为**，不是脚本坏了。

## 4. 一键判据

把三份日志传给脚本（顺序无关，缺哪个就写 UNKNOWN）：

```
.venv\Scripts\python.exe tools\verify_realline.py ^
    --run-log logs\run_YYYYMMDD_HHMMSS.log ^
    --ui-log logs\launch_runN.log ^
    --voice-log logs\voice_playback.log ^
    --min-minutes 30
```

| 退出码 | 含义 | 该怎么办 |
| --- | --- | --- |
| `0` | 三项自动判据全 PASS | **还要人工完成「未验项」**（关 App 听声、窗口真隐藏、形态 caveat）才算闭环 |
| `1` | 有 FAIL | 按输出定位；别改判据去消红 |
| `77` | 有 UNKNOWN（含什么都没喂） | 未验证，**不算通过**；补齐日志/时长/业务活动再跑 |

脚本末尾会强制打印「未验项」清单并自检非空——把它抹掉，脚本自己会判红。
这是为了守住诚实边界：**自动判据再全绿，也代替不了人耳听那 10 秒**。
