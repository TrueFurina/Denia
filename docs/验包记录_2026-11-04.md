## 2. 这一轮抓到并修掉的两个真缺陷

### 2.1 跳步 = 白屏 + 一个 crash 日志（已修）

原来 `main.py:2519` 是裸的 `cfg = load_config(args.config)`。缺 `config.yaml` 时：

```
未捕获异常（已写入 logs/crash_20261104_133956.log）:
FileNotFoundError: [Errno 2] No such file or directory: 'config.yaml'
```

窗口一个都不出现。用户看到的是"双击没反应"，而这条正是**队友最容易撞到的第一步**。

现在：`src.config.ensure_config_file()` 四态判定（exists / created / missing / error），
`main` 只负责打印。**已存在绝不覆盖**——拿模板盖用户实配是数据丢失级错误。

闸门 `tools/test_config_bootstrap.py` 16 条 + `_qc_config_bootstrap_mutation.py` 三刀全红。

### 2.2 没有 Electron 壳时，桌宠只能显示、点不到也拖不动（已如实告知）

日志原来是：

```
[WARNING] [桌宠] 渲染窗分离：native 不可用，跳过（窗口将无法拖动）
```

两层问题：

1. `getattr(pet_window, "native", None)` **只查一次**就放弃。pywebview 6.x 里
   `Window.native` 是 `__init__` 置 `None`、窗口创建完成后才由 GUI 线程填——查早了永久跳过。
2. 顺着注释去查 `webview/platforms/winforms.py::detach_pet_render()`：**pywebview 6.2.1
   里根本没有这个函数**（全仓也没有定义）。所以就算等到了 `native`，也没有东西可调。

这条分支**只在没有 Electron 壳的机器上走**（源码直跑 / 队友新装），开发机有壳从不经过，
所以一直没暴露。现在日志改成实话并给出恢复办法，README 的"桌面形象"一行同步：

```
[桌宠] 没有 Electron 壳：当前 pywebview 不提供 detach_pet_render，
       桌宠窗口只能显示、不能拖动（要拖动：cd shell && npm install）
```

**未修的部分**：真正的渲染窗分离需要自己写 Win32（找 `Chrome_WidgetWin_1` 子窗、
`SetParent` 出来）。这是独立一件事，且只在无壳路径可验证，没塞进这次。
